## 0. 背景与目的

### 为什么需要这份文档

Mira（Gemini 3）基于现有 UX Spec v1.1 产出的界面有两个核心问题：

1. **难看，易用性低**——从 spec 文字直接翻译成组件，没有经过视觉设计思考，缺乏信息层次和视觉重心
2. **不支持移动端**——PRD v0.5 已将移动端纳入 P0 必需范围，但当前原型完全没有移动端实现

本文档确立 SeatLoom 的 **视觉方向、信息架构、布局原则和组件风格**，作为后续 Mira 实现的硬约束锚点。Mira 在此框架内实现 React 组件，不允许自由发挥视觉方向。

### 设计优先原则

设计先行。先把交互设计和页面样式做到能完全体现产品用户故事中的价值，然后再进一步做 implementation。当前 Mira 的设计可以被推翻，也可以逐步修正，但必须有一个明确的设计方向作为约束。

## 1. 设计语言定位：「冷静控制台」

### 1.1 SeatLoom 的设计本质挑战

SeatLoom 不是项目管理工具，不是 IDE，也不是聊天界面。它是一个 **人机协作的监督控制台**。最接近的类比是：

- **飞行管制台**的信息密度和状态感知
- **Linear** 的简洁和键盘优先
- **Bloomberg Terminal** 的"一切信息都在一屏但不混乱"

核心矛盾是：用户需要同时感知 **全局健康状态**、**等待决策的事项**、**正在执行的工作细节**、**历史证据**，但不能让这些东西同时淹没屏幕。

### 1.2 视觉参考系

三个经 Mr. Zhang 确认的参考：

| 参考 | 提取的设计特征 |
|---|---|
| **Figma** | 专业工具感，浅色画布，紧凑但不拥挤，蓝色系主色，面板可收折，图标导航 |
| **Claude Cowork** | 现代 AI-native 界面，内容优先，结构清晰，不花哨，对话式但有结构 |
| **SaaS Dashboard** | 数据卡片驱动，指标醒目，图表辅助理解，白底 + 彩色重点，Clean grid |

合在一起，SeatLoom 的设计语言是：

> **浅色专业画布 + 数据驱动的监督视图 + 手术刀式的色彩重点**
>
> 不是花哨的仪表盘，不是聊天界面，是一个让你在 3 秒内知道项目状态、30 秒内做出决策、3 分钟内完成一次完整审查闭环的控制台。

### 1.3 Mr. Zhang 的设计偏好（已确认）

- **主题**：Light 和 Dark 都需要，但偏好 Light
- **色彩**：大面积颜色不要太多种，但局部为了突出重点可以多用颜色
- **信息**：要容易读，能容易抓住重点，能轻松进入看到细节
- **层次**：有层次，能闭环
- **Desktop 首屏**：data-driven dashboard + task workflow simulation，用于掌握全局情况、解决关键阻塞、Review 重要阶段、确保 ROI 优良
- **Mobile 核心**：确保项目阻塞、决策第一时间响应，整体被高效推进、ROI 优秀，成果物完整可见可追溯可 Review 可随时提整改意见并被后续响应

```
背景层
```


### 2.3 色彩使用原则

**关键原则：大面积用白/灰，小面积用彩色。**

彩色只出现在：
- 状态 chip（小面积色块 + 文字）
- 指标数字（仪表盘大数字可带色彩）
- 图表和数据可视化
- 操作按钮
- 紧急程度指示器

整体视觉感受是"安静的画布上有几个醒目的信号"。

```
指标数字       Inter 28px / 32px  Semibold  (仪表盘大数字)
标题 H1       Inter 20px / 28px  Semibold  (页面/模块标题)
标题 H2       Inter 18px / 26px  Semibold  (区域标题)
标题 H3       Inter 16px / 24px  Semibold  (卡片标题)
UI 正文       Inter 14px / 22px  Regular   (英文正文)
              PingFang SC 14px / 24px      (中文正文，行高略高)
密集数据       Inter 13px / 20px  Regular   (表格、列表行)
代码/路径      JetBrains Mono 13px / 20px
状态 Chip     Inter 11px / 16px  Medium    (大写英文或中文标签)
辅助文字       Inter 12px / 18px  Regular   (时间戳、次要提示)
```

### 3.3 中英混排规则

- 中文和英文/数字之间自动添加 4px 间距
- 状态、ID、角色 chip 使用一致高度（24px），防止混排时行内跳动
- 避免在同一行内混用 Latin monospace 和 CJK proportional 文字，除非用 chip 或 label 分隔

## 4. Desktop 端设计

### 4.1 整体布局架构

不用传统的"三列平铺"，而是用 **导航窄轨 + 自适应主区域 + 可收折上下文面板**：

```
┌──────────────────────────────────────────────────────────────┐
│  ◉ 项目名 │        ⌘K  说出你想做的事...             │ 同步 ● │
├────┬─────────────────────────────────────────┬───────────────┤
│    │                                         │               │
│ 📊 │   主内容区 (随导航切换)                    │  上下文面板    │
│ 📥 │                                         │  (选中项详情)   │
│ 📋 │   默认 = 监督仪表盘                       │               │
│ 📐 │                                         │  不选中时 =    │
│ 👥 │                                         │  项目概览      │
│ 📦 │                                         │               │
│ 📖 │                                         │               │
│    │                                         │               │
│    │                                         │               │
├────┴─────────────────────────────────────────┴───────────────┤
│  终端面板 (折叠态 36px, 展开 300px)                            │
├──────────────────────────────────────────────────────────────┤
│  状态栏: 项目路径 │ 同步时间 │ 协作模板 │ 运行时 │ 预算        │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 导航窄轨（48px，仅图标 + tooltip）

| 图标 | 标签 | 对应模块 |
|---|---|---|
| 📊 | 监督概览 | 仪表盘首屏（默认） |
| 📥 | 收件箱 | 行动队列 |
| 📋 | 工作项 | WorkItem / Handoff 列表 |
| 📐 | 时间线 | Timeline 事件流 |
| 👥 | 席位 | Seat Registry / Card / Role |
| 📦 | 产出物 | Artifacts 列表与搜索 |
| 📖 | Playbook | Playbook 库 |

优势：最大化内容区域，Figma 式的紧凑专业感，不会让导航栏本身变成信息负担。

### 4.3 上下文面板（右侧，可收折）

- 默认宽度 380px，可拖拽调整
- 内容完全由主区域的选中对象决定
  - 选中 Inbox 行 → 展示关联工作和证据
  - 选中 WorkItem → 展示席位、Gate、预算
  - 选中 Artifact → 展示元数据、评论线程
  - 什么都没选 → 展示 Project Overview 概览
- 可通过快捷键或按钮完全收折，给主区域更多空间

### 4.4 Master-Detail 交互模式（核心交互原则）

所有列表视图（收件箱、工作项、时间线、席位、产出物）统一使用 **Master-Detail** 模式，参考 Outlook 邮件列表/阅读窗格的交互范式：

**原则：列表不需要很宽。点击条目后，列表变窄，详情占据主要屏幕空间，让信息一览无余，减少翻页。**

**Desktop 默认态（无选中项）**

```
┌──────────────────────────────────────────────────┐
│ NavRail │  列表 (占满主区域宽度)                     │
│  48/180 │  ┌──────────────────────────────────────┐ │
│         │  │ 条目 1                               │ │
│         │  │ 条目 2                               │ │
│         │  │ 条目 3                               │ │
│         │  └──────────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

**Desktop 选中态（点击条目后）**

```
┌──────────────────────────────────────────────────┐
│ NavRail │ 列表     │  详情 (主导)                   │
│  48/180 │ 280px    │  占据剩余全部宽度                │
│         │ 变窄     │                                │
│         │ ● 条目1  │  标题、完整内容、证据、操作、      │
│         │ ■ 条目2  │  审查面板 —— 尽量不需要翻页       │
│         │ ● 条目3  │                                │
│         │          │                                │
└──────────────────────────────────────────────────┘
```

**Tablet (<1024px) 选中态（列表完全隐藏）**

```
┌──────────────────────────────────────────────────┐
│ NavRail │  ← 返回 │ 详情 (全宽)                     │
│  48     │         │                                │
└──────────────────────────────────────────────────┘
```

**Mobile (<768px) 选中态（底部上滑 sheet）**

列表为全宽单列卡片流。点击后详情以底部 sheet 形式上滑，可半屏或全屏。

设计规则：
- 列表缩窄到 280px 时，每行只保留：优先级指示器 + 标题 + 次要信息一行 + 时间戳
- 详情区域铺满剩余空间，最大化信息可见面积
- 点击返回按钮或按 `Escape` 恢复列表全宽、隐藏详情
- 列表缩窄/展开使用 200ms ease 过渡动画
- 当前选中项在窄列表中用蓝色左侧竖条 + 浅蓝背景高亮
- 详情视图应以最少翻页为目标进行信息排布

### 4.5 模式驱动的主区域

主区域根据导航位置切换工作模式，所有列表模式统一使用上述 Master-Detail 交互：

| 模式 | 用户意图 | 列表内容 | 详情内容 |
|---|---|---|---|
| **监督模式**（默认） | "今天什么需要我处理？" | 不使用列表——仪表盘全屏展示 | — |
| **收件箱模式** | "哪些事等我决定？" | 按优先级排序的行动队列 | 选中项的完整上下文、证据、操作按钮 |
| **工作模式** | "我要看具体工作细节" | WorkItem/Handoff 列表 | Gate 状态、证据、席位、操作 |
| **时间线模式** | "发生了什么？" | 按时间排序的事件流 | 事件关联的对象和证据 |
| **席位模式** | "谁在做什么？" | 席位/会话树 | Seat Card、角色、能力、预算 |
| **审查模式** | "我要审阅产出物" | 产出物列表（带过滤） | Artifact Reader + Review Rail |
| **Playbook 模式** | "有什么可复用的？" | Playbook 列表 | Playbook 详情和来源证据 |

### 4.5 Supervisor Command Bar

`Cmd/Ctrl+K` 打开的 Command Bar 是用户 80% 操作的起点。

设计要求：
- 宽度 640px，居中浮层
- 占据视觉最高层级（overlay + 背景暗化）
- placeholder: `说出你想做的事...`
- 支持自然语言输入，也支持对象 mention（如 @WI-012, @Mira）
- 输入后返回 Suggestion Card（结构化提案），支持 Confirm / Edit / Cancel
- Edit 模式是 inline 编辑，不跳转到新表单

这不是一个搜索框，是产品的 **核心交互面**。视觉上它应该是屏幕上最醒目、最有存在感的元素。

## 5. 监督仪表盘（Desktop 默认首屏）

这是用户打开 SeatLoom 第一眼看到的东西，必须在 3 秒内回答四个问题：

1. 什么需要行动？
2. 谁在做什么？
3. 哪里堵了？
4. 预算/ROI 怎么样？

### 5.2 区域设计要点

**顶部指标卡（L1 扫描层）**
- 5 个卡片并排，高度 80px
- 大数字用 28-32px Semibold，标签用 12px 次要灰色
- 数字颜色跟随状态语义（待决策用琥珀色，阻塞用红色，健康用绿色）
- 指标卡可点击，跳转到对应的过滤列表
- 3 秒扫完全局健康

**工作流全景（task workflow simulation）**
- 不是甘特图，是一个 **简化的席位流转可视化**
- 节点表示席位（Lyra / Mira / Nimbus / Flux），连线表示工作流转方向
- 每个节点显示当前在手的工作数量和状态
- 阻塞的节点用红色边框高亮
- 时间范围可切换（今天 / 本周 / 全部）
- 让用户一眼看到工作在哪个节点、哪里堵了

**行动队列（需要你行动）**
- 不是通知列表，是"等你做决定"的清单
- 每行包含：优先级 chip、动作类型、对象引用、负责席位、等待时间
- 按等待时间排序，红色最紧急在最上面
- 行可点击，在右侧上下文面板展开详情
- 行内可直接展示快捷操作按钮（审批/拒绝）

**最近活动**
- 只展示最近 5-8 条，纯信息流
- 不需要行动的信息，只是让用户感知"项目在活着"
- 点击可跳转到时间线的对应事件

## 6. 信息层次模型

### 6.1 三层模型

| 层级 | 展示位置 | 信息量 | 用户行为 | 完成时间 |
|---|---|---|---|---|
| **L1 扫描层** | 仪表盘指标卡、状态 chip、行动队列行 | 数字 + 一行描述 | 判断"需不需要管" | 3 秒 |
| **L2 决策层** | 点击行动项后的上下文面板 / Suggestion Card | 关键上下文 + 证据链接 + 操作按钮 | 做一个决策 | 30 秒 |
| **L3 深度层** | Artifact Reader、Session 终端、Evidence 搜索 | 完整内容 | 深度审查 | 3-10 分钟 |

用户 90% 的时间在 L1-L2 之间完成工作。L3 只在需要时才进入。

### 6.2 渐进式展开原则

- L1 默认可见，不需要任何点击
- L2 通过点击行或卡片进入，在上下文面板或浮层中展示
- L3 通过明确的"打开完整内容"操作进入，会占据主区域
- 每个层级之间必须有明确的视觉边界（面板切换、页面跳转、或 overlay）
- 不允许在一个面板内混合三个层级的信息密度

## 7. Mobile 端设计

### 7.1 设计原则

Mobile 不是 Desktop 的缩小版。Mobile 是一个 **决策加速器**：

- 确保阻塞被第一时间解除
- 确保关键审批不被拖延
- 确保短反馈能即时回到工作循环
- 确保成果物可随时快览和提意见
- 确保整体被高效推进、ROI 优秀

Mobile 明确 **不做** 的事情：
- 不创建工作项（提示"在桌面创建"）
- 不做完整的 Artifact Review（只有快览 + 留言）
- 不做终端操作
- 不做长文本编辑

### 7.3 底部四个 Tab

| Tab | 作用 | 核心内容 | Desktop 对应 |
|---|---|---|---|
| **概览** | 健康指标 + 风险信号 | 3 个核心数字 + 推荐下一步 | 仪表盘指标卡 |

| **活动** | 最近时间线事件 | 只读事件流 | Timeline |
| **成果** | 关键产出物快览 | 产出物列表 + 提意见入口 | Artifacts（简化） |

### 7.4 Mobile 三个核心场景

**场景 1：巡检（30 秒内完成）**

用户在路上，掏出手机看一眼：项目还好吗？有什么需要马上处理的？

- 展示：项目健康指标 + 阻塞数 + 待审批数 + 一句话推荐下一步
- 入口：概览 Tab

**场景 2：决策（1 分钟内完成）**

收到推送通知：有一个 Gate 需要审批 / 有一个 Prompt 被阻塞了。

- 展示：Action Card → 关键上下文 + 证据摘要 → Approve / Reject / Escalate / 留到桌面处理
- 入口：行动 Tab 或通知深链

**场景 3：反馈（2 分钟内完成）**

看到一个交付物的摘要，想留个简短意见。

- 展示：目标对象 + 状态 + 有界文本输入 → 发送后反馈直接回到桌面的工作循环
- 入口：成果 Tab → 点击成果物 → 留言

### 7.5 Desktop vs Mobile 关键差异

| 维度 | Desktop | Mobile |
|---|---|---|
| 指标卡 | 5 个并排，含图表趋势 | 3 个核心数字，无图表 |
| 行动项 | 行级展示，点击进 Detail 面板 | 卡片式，内嵌操作按钮 |
| 证据查看 | 完整 Artifact Reader + Review Rail | 有界摘要 + "在桌面查看" |
| 输入方式 | ⌘K Command Bar + 键盘快捷键 | 预设操作按钮 + 短文本框 |
| 审查 | Review Rail + 行内锚点评论 | 只有"留言"和 mode chip |
| 创建 | 完整的 Supervisor 提案流程 | 不支持。提示"在桌面创建" |
| 信息范围 | 完整——所有模块、所有历史、所有细节 | 过滤——只展示需要行动或关注的 |
| 交互深度 | 创建、编辑、审查、终端操作、全文搜索 | 审批、短反馈、快览、留到桌面 |
| 视觉密度 | 高密度多面板 | 单列卡片流，大触控区域 |

## 8. 组件设计原则

### 8.1 卡片（Card）

- 白色底 + 轻微圆角（6-8px）+ 1px 浅灰边框或微妙投影
- 不要用深色边框或粗线条
- 卡片内信息按重要性从上到下排列
- 状态 chip 在右上角或行首

### 8.2 状态 Chip

- 高度 24px，圆角 12px（全圆角）
- 浅色背景 + 同色系深色文字 + 左侧小圆点
- 示例：`🟢 运行中`  `🟡 需关注`  `🔴 阻塞`  `⚪ 已完成`

### 8.3 操作按钮

- 主操作：填充蓝色按钮，白色文字，圆角 6px
- 次要操作：透明底 + 蓝色文字，带 1px 蓝色边框
- 危险操作：填充红色按钮
- 按钮高度 36px（Desktop）、44px（Mobile，适配触控）
- 按钮之间间距 8px

### 8.4 列表行

- 行高 48px（Desktop），56px（Mobile）
- 左侧：优先级/状态指示器（4px 宽色条或圆点）
- 中间：标题 + 次要信息
- 右侧：时间戳或操作按钮
- hover 时背景变浅灰
- 选中时左侧色条变为主色蓝

### 8.5 面板和分隔

- 面板之间用 1px #E5E7EB 分隔线
- 不要用粗分隔线或色块分隔
- 区域标题用 12px 大写灰色字母（ACTIONS / RECENT / WORKFLOW）
- 区域之间的垂直间距 24px

### 8.6 数据可视化

- 图表使用 4 色系列：蓝、紫、蓝绿、琥珀
- 背景为白色，网格线用极浅灰（#F3F4F6）
- 图表标题用 H3 样式
- 图表必须有可交互 tooltip

## 9. Inbox 设计要点

Inbox 不是通知列表，是 **行动队列**。

### 9.1 过滤原则

- Inbox 里每一行都意味着"需要你做一个决定"
- 不需要决定的东西不应该出现在 Inbox
- 默认过滤：只显示需要人类行动的项目
- 已完成/已取消的项目自动从 Inbox 消失

### 9.2 行设计

每行必须能在不展开详情的情况下，让用户判断紧急程度和需要的动作类型：

```
┌─────────────────────────────────────────────────────┐
│ 🔴 │ Gate 审批 │ WI-012 UI 基线验证 │ Flux │ 23分  │
├─────────────────────────────────────────────────────┤
│ 🟡 │ Prompt 阻塞│ S-003 编译会话     │ Nimbus│ 8分  │
├─────────────────────────────────────────────────────┤
│ 🔵 │ 交付确认  │ WI-015 存储层      │ Mira  │ 2分  │
└─────────────────────────────────────────────────────┘
```

左色条表示紧急级别（红 > 琥珀 > 蓝 > 灰）。

## 10. Artifact Review 设计要点

### 10.1 审查模式布局

审查模式进入后，主区域被 Artifact Reader 接管：

```
┌──────────────────────────────────────────────────────┐
│ ← 返回 │ 文档标题                  │ 在编辑器打开 │ 复制 │
├──────────────────────────────────────────────────────┤
│ [Task Packet] [verification]  v1 · aegis · 2026-04-29│
├─────────────────────────────────┬────────────────────┤
│                                 │                    │
│  Markdown 内容区                 │   Review Rail      │
│  section badges (评论数)         │   评论线程列表       │
│  行内锚点 (选中文本)              │   活跃/已解决/争议   │
│                                 │                    │
│                                 │                    │
├─────────────────────────────────┴────────────────────┤
│ 搜索文档 │ 添加评论 │ 请求修改 │ 查看版本                │
└──────────────────────────────────────────────────────┘
```

### 10.2 文档类型标识

- 家族徽章 + 子类型 chip 在文档标题下方
- 元数据条（id, status, author, date, version）在徽章行下方
- 类型特定摘要块在元数据条下方、正文上方
- 用户先看到结构化元数据，再进入 markdown 正文

## 13. 基于确认结果的设计补充

### 13.1 可收折导航栏

导航栏有两个状态：

**收起态（48px，图标 + tooltip）**

```
┌────┐
│ 📊 │  ← tooltip: "监督概览"
│ 📥 │  ← tooltip: "收件箱"
│ 📋 │  ← tooltip: "工作项"
│ 📐 │  ← tooltip: "时间线"
│ 👥 │  ← tooltip: "席位"
│ 📦 │  ← tooltip: "产出物"
│ 📖 │  ← tooltip: "Playbook"
│    │
│ ◀▶ │  ← 展开/收起按钮
└────┘
```

**展开态（180px，图标 + 文字标签）**

```
┌──────────────────┐
│ 📊  监督概览       │
│ 📥  收件箱    3   │  ← 未处理计数
│ 📋  工作项        │
│ 📐  时间线        │
│ 👥  席位          │
│ 📦  产出物        │
│ 📖  Playbook     │
│                  │
│ ◀  收起          │
└──────────────────┘
```

设计规则：
- 收起/展开使用 200ms ease 过渡动画
- 展开态导航栏中，当前活跃页用左侧 3px 蓝色竖条 + 浅蓝背景高亮
- 收起态中，当前活跃页用蓝色图标标识
- 收件箱等可在图标右上角显示未读/待处理计数 badge
- 用户偏好（收起/展开）持久化到本地存储

### 13.2 响应式 Web 的 Mobile 适配

因为选择响应式 Web 而非原生 App，以下设计约束生效：

**Breakpoint 规则**

| 视口宽度 | 布局模式 | 导航 | 主区域 | 上下文面板 |
|---|---|---|---|---|
| ≥ 1280px | Desktop 完整模式 | 可收折侧栏 | 主内容 + 右侧面板 | 可见 |
| 1024-1279px | Desktop 紧凑模式 | 收起态侧栏 | 主内容 + 右侧面板 | 可收折 |
| 768-1023px | Tablet 模式 | 收起态侧栏 | 主内容全宽 | overlay 抽屉 |
| < 768px | Mobile 模式 | 底部 Tab Bar | 单列卡片流 | 底部 sheet |

**Mobile 模式特殊规则**
- 左侧导航栏完全隐藏，替换为底部 4 Tab Bar（概览/行动/活动/成果）
- 上下文面板变为底部上滑 sheet（half-screen 或 full-screen）
- Command Bar 变为页面顶部搜索入口（点击展开 overlay）
- 终端面板在 Mobile 下不可用（展示 "在桌面查看" 提示）
- 所有按钮触控区域最小 44×44px
- 卡片间距加大到 12px（Desktop 为 8px）

**共用代码库约束**
- 组件使用 CSS media query 或 container query 适配
- 不要为 Mobile 创建完全独立的组件树——用同一组件的响应式变体
- 数据层和状态管理完全共用
- 路由结构共用，Mobile 下部分路由隐藏或重定向
