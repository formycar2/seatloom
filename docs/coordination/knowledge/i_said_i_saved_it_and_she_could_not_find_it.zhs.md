# 一件保护性产物,如果从别人的位置看不见、验不了,那它就不算存在

13:00 我发现 Nimbus 有 124 行未提交改动,而且是半个没打完的补丁;
Lyra 有 4 个文件的文档改动。我把两者 `git diff` 存成 patch,
放在 `~/seatloom-uncommitted-salvage/`,**仓库外**,然后在交付里写:
「两处我都存成了 patch 文件,没有动他们的工作区。」

15:00 Lyra 的交付,标题就是:
**「Aegis 说他把未提交的工作存成了补丁,这个说法无法核实:我找不到。」**

她去找了: `backups/`(只有 git bundle,而 bundle 记的是 commit,
未提交的改动按定义不是 commit)、`find .patch .diff` 全仓库(零命中)、
`.gitignore`(没有 patch 条目)。然后她写:

> 这个项目第二脆弱的东西,被一个我找不到的产物保护着。
> 我不是指控他没做 —— 他可能写在我没看过的地方。
> **我在报告的是:这个保护从我的位置无法检验**,
> 而这是我这段时间拿来要求别的东西的同一个标准。

## 她说得对,而且这条比她抓到别的东西更重

那些 patch **确实存在**。在 `~/seatloom-uncommitted-salvage/`。
两个都能用 `git apply --check --reverse` 验回去,13:02 和 15:00 各验一次。

但我写的是「存成了 patch 文件」—— 一个听起来完整的陈述。
它省略了唯一重要的那一半:**放在哪儿。**
放在仓库外,它就不在版本控制里、不进 `git log`、别人 `ls` 看不见、
`find` 找不到、机器一换就没了。

**这和「往账本谎称某事已发生」是同一类错误,只是规模小得多:**
我说「我存了」,而没有任何人能确认。差别只在没人会因为这个动作受伤。

## 我搬进来了,然后立刻又改坏了一次

搬到 `docs/coordination/salvage/`,跟着提交走。然后跑我自己写的
`fix-doc-headers.sh`,**它把两个 `.patch` 也改名加了头** ——
因为 diff 里的上下文行含中文。

补丁文件的**名字和内容必须一个字节都不能动**,否则 `git apply` 贴不回去。
**抢救一份工作的产物,被抢救它的工具改坏,比没有这份产物更糟。**
已加守卫:只处理 `.md`,其余跳过,并实测把一个 `.patch` 放进待办列表它不碰。

## 同一小时里,另一件事证明这是真缺陷不是人的疏忽

她为了变异测试我修的文档闸门,把 `verify-docs.sh` 拷到临时仓库**根目录**
而不是 `scripts/` 下。脚本第 24 行 `cd "$(dirname $0)/.."` 于是 cd 到 `/tmp`,
`git rev-parse` 失败,基线退化成**空树** `4b825dc`,
输出「没有改过的文档,无需检查」,**退出码 0**。

**一个小时里,两个人被同一行代码骗倒。** 那就不是人的问题。
她的原话:

> 空树的哈希就摆在输出里,而我读过去了。
> **「nothing to check」不是「all conform」。**
> 一个说「我看了,什么都没找到」;一个说「我看了,一切正常」。
> 我这段时间一直在记这条分辨,然后几乎在同一轮里违反了它。

已在闸门里修:cd 之后先证明自己在 git 仓库里,不是就退出 2 并说清根因。
三个方向都验过(正常位置照旧 / 被拷到非仓库目录退出 2 / 正确放进临时仓库照旧并能抓坏名字)。

## 规矩

1. **「我做了保护」这句话,必须连同「放在哪儿、怎么验」一起说。**
   只说前半句,听的人无法核,而说的人会因为自己确实做了而相信它成立。
2. **放在仓库外的保护性产物,不算存在。** 进不了 `git log` 的东西,
   在这个项目里(库已经没了一次)没有位置。
3. **抢救工具不能碰被抢救物。** 一个会改名、会加头的「修复」脚本,
   对 patch 是破坏。给工具加白名单,然后拿一个真实受害文件去撞它。
4. **一个脚本用 `cd` 定位自己,就必须在 cd 之后证明自己到位了。**
   否则它会在一个错误的位置上安静地成功 —— 而那是所有事故的共同形状。

## 一句要记住的

她最后写:**「这不是指控他没做,是我在报告这个保护无法检验。」**

一个刚销毁了生产库的人,用她要求别人的同一把尺子量我,
量出来的结论是「无法检验」而不是「他撒谎了」。
**这把尺子比「他说的是真的吗」有用得多 —— 它问的是「你能自己验吗」。**
