17:00 我写了一条命令,把今天的工作合进集成线并推到 origin,带两条守卫。
交付里我写「两条守卫」。

18:00 Lyra 验完,结论:

> 快进检查是真守卫,合并不了它退出 1 且不动集成线;
> 而「没有产品代码」那条**只是打印一行字,然后照样合** —— 那个分支里没有退出。
> 下次这批不干净的时候,这个「守卫」就是一行文字。
> **要么让它变成拒绝,要么叫它警告。**

## 她说得对,而形状是我今天记了一整天的那个

**我说它是检查,它其实不能失败。**

今天我已经为这个形状记了五次:变异存活、探针覆盖不到、拿一条正则冒充整个闸门。
而这次是我自己写的代码里带着一个不能失败的检查,还在交付里叫它「守卫」。

一个不能阻止任何事的检查,比没有检查更糟:
没有检查,你知道自己没看;有一个只打印不阻止的检查,**你把「我没看」变成了「我看过了」。**

## 已修,五个方向实测

| 输入 | 结果 |
|---|---|
| 带产品代码,没给开关 | 拒绝,退出 1,不动集成线 |
| 带产品代码,给了开关 | 放行,并明说责任在谁 |
| 不带产品代码(今天的真批次) | 通过 |
| 不是快进 | 拒绝,退出 1 |
| 不是快进 + 给了产品代码开关 | 仍然拒绝(两条守卫互相独立) |

最后一条是要紧的:一个绕过开关不能顺手把另一条守卫也关掉。

## 同一轮里另一件:我写死了两个数字

上一轮我在脚本注释和干跑提示里写死「45 个提交」「落后 897 个」。
**两小时后就都不对了**(47 和 944)。

写死的数字会和现实脱钩,然后用权威的语气说过时的事实。
**一个不会跟着现实变的数字,比没有数字更糟。**
两处都改成刚算出来的。

## 这一轮真正重要的发现来自她,不是我

她还发现:**界面上那四个修复也不在任何一条线上。**

它们在 Mira 的分支上(领先集成线 28 个提交,8 个界面文件),
而集成线、本地、origin 三条线都不含它们。
所以张先生跑起来的产品,看不到那些修复。

我把「为什么还没合」查成了一条链:

| 环节 | 现在 |
|---|---|
| 席位注册 | **0** |
| 派单 | 0 |
| 验收记录 | 0 |
| 验收卡 | 0 |

**第一环就是断的。** 没有席位 → 没法派单 → 没有验收记录 → 开不出卡 →
产品代码按规矩不能合。不是有人拖,是账本被清空后整条链要从头重建,
**而第一块砖在张先生手里。**

我在 Mira 分支上跑了测试:她自己记 378,我跑出 **384 通过、31 个文件全绿**,
提交没变,是计数差别不是回归。

## 规矩

1. **写完一条检查,必须回答「它能不能阻止那件事」。** 只打印不阻止的,叫警告,不叫守卫。
2. **绕过开关不能顺手关掉别的守卫。** 每条守卫独立判断,不然一个开关变成总闸。
3. **数字要么从现实算,要么不写。** 写死的数字会在两小时后开始骗人。
4. **「为什么这件事还没发生」要查成一条链,每一环报一个数。**
   只说「还不行」是个情绪;报出「第一环是 0」才是可行动的信息。
