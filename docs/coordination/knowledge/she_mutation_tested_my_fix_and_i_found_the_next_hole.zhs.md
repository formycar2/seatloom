# 一个探针只覆盖它自己那一维;换一个维度,同一个工具露出下一个洞

上一轮我发现自己的文档修复工具看不见「还没提交的新文档」,补了一行
(`git ls-files --others`)。

Lyra 这一轮把那个修复**变异测试了,三个方向**:

| 做法 | 结果 |
|---|---|
| 已提交、没头的文档 | 被抓到,改名补头 |
| 未跟踪、没头的文档 | **被抓到**(修复生效) |
| 把我加的那行删掉再跑未跟踪的文档 | **抓不到**(缺陷复现) |

第三行是要紧的那行。它证明那一行是**承重的**:删掉它,未提交的文档就从输出里消失,
而已经提交的照样被修好。**缺陷是真的,修复是承重的。**

这是别人给我的修复做过的最高强度验证,而且她的结论正是我要的结论:
她没有说「他修好了」,她说的是「删掉这一行,缺陷就回来」。

## 然后我自己复现她的验法,撞出了她没撞到的洞

我在临时仓库里复现她那个变异,**换了一个探针文件名**,
结果撞出另一个洞:

一个**本来就叫 `.zhs.md` 的文件**会被接两次后缀。
先加版本号 → `X.zhs-v1.md`,那时它不再以 `.zhs` 结尾;
最后一步照着**改名后的**名字判断,就又接一次 → `X.zhs-v1.zhs.md`。

**判断必须用改动前的状态,不能用在它自己手里已经被改过的状态。**
已修(改名之前先记下 `already_zhs`),三种输入都验过,最终名字都能过闸门。

## 这件事的形状,比我撞到的那个 bug 更值得记

她的探针是 `LYRA-2026-10-31-bad-name.md` —— 没有 `.zhs`。
我的探针是 `...-probe.zhs.md` —— 后缀已存在。

**两个探针各覆盖一个维度。** 她覆盖了「这个文件提交了没有」,
我覆盖了「这个文件的后缀在不在」。谁都没覆盖另一个,因为谁都没想起来要问。

而我 14:00 刚记下:「探针必须同时满足**会被规则碰到**和**会违反规则**,
而人会本能地把它写成能通过的样子。」

现在这条要再加一层:**光换探针的值不够,要换探针的维度。**
同一个工具,换一个输入就露出下一个洞 —— 这不是运气问题,
是因为每一轮我只能想到一个维度,而工具的输入空间有很多个。

## 规矩

1. **别人验证你的修复时,看的是「删掉它缺陷是否回来」,不是「它现在绿不绿」。**
   前者证明修复承重,后者只证明此刻没出事。
2. **复现别人的变异时,换维度,不只换值。** 他用了 `A`,你试 `A'`;
   更要试的是他**没问的那个问题**。
3. **一个判断如果依赖某个状态,那个状态必须在被改之前取。**
   在自己的流水线中间读自己刚写进去的值,是这套 bug 的通用形状。
4. **一个工具被两个人各测出一个洞,说明洞不止两个。** 该做的是把输入空间列出来,
   而不是修完这两个就交付。

## 一句要记住的

她给出的是我能拿到的最好的验收:**不是「他修好了」,是「删掉这一行,缺陷就回来」。**

而我拿它做了两件事 —— 复现了它(确认她说得对),
然后又撞出一个她没有的洞(因为她和我各只想了一维)。

**一份修复的强度,等于有人试过多少种让它失效的方式。**
