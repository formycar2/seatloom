# Aegis 心跳交付 — 2026-10-31 00:00

## 变了什么

### 我独立验了 Nimbus 补的原子性测试,它真的钉住了

上一轮我发现「主题能关闭」那张卡的验收报告自己说:
「事务原子性,这个功能的核心主张,没有任何测试钉住它。」
我派了 Nimbus 去补。他补了:`crates/seatloom-core/tests/topic_close_atomicity.rs`,
两个集成测试。

**关键在于他怎么让事务中途失败** —— 他用了一个
`DEFERRABLE INITIALLY DEFERRED` 约束触发器,只在 COMMIT 时才抛异常。
这样第一条语句是先写进去、再被回滚的。如果用普通坏值,
失败会发生在 UPDATE 自己身上,那就什么都没证明。

我自己跑了,并且做了两个变异:

| 变异 | 结果 |
|---|---|
| 删掉 UPDATE、保留事件 | **2 个测试全红** |
| 删掉事件 append、保留 UPDATE | **1 个测试红** |

恢复后两个全绿,工作区干净。**那个核心主张现在真的被钉住了。**

而且那个测试自己拒绝 live 库(库名是 `seatloom` 就直接退出),
跑在一个独立的 scratch 库上。这点做得对。

### 我在验证过程中差点犯一个错,已经记下来了

做第二个变异时,我用「取这个符号最后一次出现」的写法定位代码。
那个文件里有 **10 处**一模一样的调用,最后一次在**派单决策路径**上,
和我要测的 `close_topic` 一点关系都没有。

两个测试全绿。我差点写下「删掉事件测试还是绿的,这个测试有个洞」。

救我的只有一步:下结论前跑了 `git diff`,它明确显示我改的是别处。
按函数边界重新定位,这次 1 个测试红。

**这是「我测错了代码」的第六个形状。** 前五个是测错文件、测错目录、
测错分支;这次是**测对了文件、测错了函数**。已经写进知识库。
