## 这一轮我还是派不了活

**六个核心席位还是只有 1 个注册在账本里。** 集成线停在 10-30,
我的分支领先它 64 个提交,在 origin 上不存在。

```bash
bash scripts/register-fleet-seats.sh --apply
bash scripts/land-aegis-packet-branch.sh --apply
```

## 变了什么:她用一条 glob 把别人的未提交工作带进了提交,然后选择不藏

她这一轮本来在做一件好事:把我上一轮那条规则
(「驳斥一句假话的时候不要原文照抄」)用在她自己那四份引用了我的假话的交付文档上。

**那部分工作是好的,在同一提交里。错的是旁边那一件。**

她用 `git add -A`(一个目录 glob)代替点名文件,把两份她本轮没碰的文件扫了进去。

第一份她提交前发现并撤了。**第二份是一行 `version v2→v3`,她没发现,进了提交。**

而那一行本来躺在工作区里,**未提交、无主** —— 有人改到一半放下,glob 拿走了它。

她的原话:

> 版本号是一次声明:它说这份文档现在是第 3 版,
> 而一份受管合同的 v3 和 v2 是不同的合同。
> **我把我的名字和今天的日期贴在了它上面,却不知道 v3 说了什么、是谁声明的。**

她做对的两件事:**没有** `--amend` 掉它(改写历史来藏错,和犯错是同一类),
**也没有** revert 回 v2(v2/v3 该是哪个是你要定的事,她没有证据)。
它留在那个提交里,可见。

> 一个预先存在的脏文件不是邀请,**是信号** ——
> 有人正在编辑到一半。面对一个你不理解的信号,正确的反应是问,不是提交。

## 我先审计了我自己

我这 64 个提交**全部**用 `git add -A`。我逐个查了:
没有一次拿走别人的东西 —— 那些提交只碰我自己的交付、我写的知识记录、脚本、存档。

**但那是运气**:我的仓库里恰好没有别人的脏文件。
别人的工作区有(Nimbus 124 行、她的 4 个文件),而我从来不往那些目录 add。

## 然后我把这条规则变成了一条会失败的检查

提交前会查:**这次提交带进来的文件里,有没有别的席位目录下的。**

三个方向都实测:

| 做法 | 结果 |
|---|---|
| 只提交我自己的文件 | 放行 |
| glob 扫进别人的文件 | **拒绝,退出 1,提交没发生** |
| 明确点名别人的文件 | 仍然拒绝(规则是点名之后还要确认) |

## 而我写这条检查时,第一版判据也是错的 —— 我自己测出来的

我第一版用「工作区里有脏文件」当判据。在临时仓库里测,**它不触发**,
而那个提交照样把别人的文件带走了。

原因:**被 glob add 之后,文件已经在暂存区里了**,
「工作区有脏文件」这个判据恰好看不见它。

**一个 glob 犯罪的后果,正好让针对 glob 的检查失效。**

改成看「这次提交带进来什么」之后,它才真的会失败。

## 还有一件:我上一轮说「已提交」也是假的

我上一轮把检查写进 `.git/hooks/pre-commit`,然后报「已提交」。

**假话。** `.git/hooks` 不在版本控制里,`git add -A` 看不见它,
那次提交实际什么都没发生(输出写着「没有要提交的」,而我从尾巴上读过去了)。

这正是我昨晚 23:00 记下的那条:**一个只存在于工作区的修复,等于不存在。**
这次更隐蔽 —— 上次是改动被重置丢掉,这次是改动从来就不在 git 看得见的地方。

现在检查放在 `.githooks/pre-commit`,进了版本库,换个克隆也带着它。


**那份合同文档该是 v2 还是 v3,只有你能定。** 证据在她的提交里,一行,两个方向都容易改。
她说她不是该做这个决定的人,我也同意。
