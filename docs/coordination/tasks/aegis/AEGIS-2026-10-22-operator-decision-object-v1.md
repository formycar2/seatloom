## 先说为什么

价值设计里 V3 的原话:**「只有他能决定的事,要自己来找他」**。

现状我核过(不是推测):

- 数据库里**没有任何待决对象表**(无 decision / pending / obligation 相关表)
- `fleet-status.sh` 的「等你拍板」**只读 `acceptances` 表** —— 也就是只看验收卡

**后果:产品方向的裁定、只有操作者能解的前置条件(比如"要不要给防护加豁免"、
"沙箱连哪个库"、"删不删那个文件"),全都只以 SupervisorMessage 的形式存在。**
账本里有记录,但没有一处结构化的地方能回答"现在有几件事在等他、都关于什么"。

V3 文档把这件事的失败模式写得很准:**「他目前靠读消息或被告知才知道这些。成本最高的
失败模式是静默遗漏。」**

## 张先生已授权的那四条判据(2.3,10-20)

他 10-20 说「你来判断即可」,我据此划了边界。这一单不做新的产品决定,
**只是把我划的判据落成可执行的规则**:

**必须由操作者决定:**
1. **动钱、动上线、动对外** —— 合并交付、发版本、花钱
2. **改我给别人的指令本身** —— 改派单内容、改验收标准
3. **改变产品给别人看的样子** —— 默认范围、导航、显示什么

**Aegis 定,不占用他:**
- 活派给谁、怎么拆、什么时候发门事件
- 技术选型、改哪些文件
- 内部记账怎么组织

判据一句话:**影响不到他的,就别占用他。**

## 要做的事

### 一、一个结构化对象(表 + MCP 工具)

字段至少覆盖价值设计第 5 节要求的五样:

| 字段 | 为什么必须有 |
|---|---|
| `target` | 要决定的**具体东西**是什么(不是一段话) |
| `choices` | 合法选项是什么。只有一个选项就不叫选择 |
| `decider` | 谁有权定。**默认是操作者,但不默认成所有事都推给他** |
| `status` | pending / resolved。必须能查"现在有几件在等他" |
| `consequence` | 定了之后会怎样。不说后果的选择是让他在黑箱里点 |
| `evidence` | 支持这项决定的证据链(哪个派单、哪条验绿、哪个裁定) |

**这不是消息表。** 判据:一条消息不构成决策义务。被阻塞的派单、失败的读取,
大多数属于席位或我,不是他。

### 二、入口(界面 + 汇报)

1. `fleet-status.sh` 的「等你拍板」**不能只读 acceptances** ——
   要把这个新对象的 pending 项一并列出,并标明"这是验收"还是"这是裁定"
2. 界面要有地方看(具体哪一屏你定,但**不许因此改第一屏结构** —— 那是等张先生拍板的事)

### 三、谁能创建

- **只有操作者和 Aegis 能创建。** 席位不能给自己造一个"等他决定"来推工作
- 创建时必须给 `choices` 和 `consequence`,**缺一个就拒绝** ——
  一个说不清后果的待决项,比没有更糟(它会让他以为点一下就行)

## 验收

1. 存在一条命令能回答「现在有几件事在等操作者」,且**答案与界面显示一致**
2. `choices` 或 `consequence` 缺失时,创建被**拒绝**且错误信息说清缺哪个
3. 席位身份创建被拒绝(不是"允许但不推荐")
4. resolved 之后不能再改(账本不可改,和历史裁定同一规矩)
5. 加测试:创建缺字段被拒、席位创建被拒、resolved 后不可变
6. 迁移可重复跑(幂等),且**不灌任何种子数据** ——
   一个凭空出现的"待你决定"是污染,不是功能
7. cargo build/test/clippy/fmt 全过;测试不许恒真

## 明确不做

- **不判定任何具体事项该归谁** —— 那是我(Aegis)的职责,我另有一份待办去划
- 不改第一屏结构、不加导航(那两件等他拍板)
- 不把现有验收卡搬进这个新对象(它们是不同的东西,别混)
- 不动 live 数据库(迁移由张先生执行,脚本要 dry-run 默认)
- 不合并、不自己开验收卡
