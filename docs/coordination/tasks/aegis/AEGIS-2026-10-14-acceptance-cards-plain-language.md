# 验收卡人话重写(张先生 2026-10-14)

**触发**:张先生原话「这些都没办法验收,我看不懂,现在我看到 4 个合并的卡,其中的描述无法让我完成测试,不清不楚,奇怪 Flux 还能通过测试,真是不可思议」。

**根因(我的)**:派单时没把「张先生能照着测」写成可验条件。Flux 验的是技术判据
(工具注册、测试、fmt/clippy),那个它判得了;「操作者能不能读懂」从来不在任何派单的判据里。
**不是 Flux 放水,是我没出这道题。**

## 为什么我不自己改卡

- MCP 工具面**没有 `update_acceptance`** —— 只能建卡或作废,没有「改」
- `cancel_acceptance` 有**席位置身性守卫**(注释原文:"the seat pulls back its OWN pending
  acceptance request")—— 只有提请席位能撤自己的卡,那 3 张是 mira/vela 提请的

所以正解是**派单让提请席位作废重开**,不是问张先生「我可以改吗」。

## 人话判据(缺一条不算合格)

1. 全中文,不出现 S0/S1/S2/S2.5/L2/typed record/confidence/quoted/inferred 等术语
2. 写清:看什么 → 看到什么算对 → 什么算打回
3. 从没读过代码的人能照着走完
4. 不用自造缩写,不引用派单标题

## 三张卡的参考写法

### acc-disp-supervisor-intent-ui-wiring(意图入口,mira)

1. 打开 SeatLoom,在监督者面板的输入框里打一句:「给后端席位派一张单,把唤醒服务的硬底兜底接上」
2. 看它回什么:应该出现一张提案卡,上面写清楚**派给谁、为什么派给它、预算是多少、依据是什么**
3. **关键一步** —— 故意打一句含糊的,比如「那个东西弄一下」:它必须**停下来问你**「你要做哪一种」并给出选项,而不是自己猜一个。猜了就是打回。
4. 点提案卡上的确认,然后到派单列表里找这张单:它应该在,而且记录的操作者是**人**,不是 agent。

### acc-disp-wash-vela-p1(清洗前半段,vela)

1. 打开 SeatLoom 的知识面板,看主题树:这些主题是从你 16 个历史会话里分段出来的。
   **逐个问自己「这是一个独立的工作主题吗」**。
2. 找一条带密钥样式的文本,确认它显示的是 `⟪REDACTED:类型:指纹⟫` 而不是原文。
3. 点任意主题进去,看它的记忆条数是不是比原始会话少很多(砍掉了 80-90%),
   但点开每条记忆给的行号,还能打开你当时的会话原文。
4. 第 1 步里如果有哪个主题明显切错了(两个不相关的活被并成一个),写打回理由。

### acc-disp-wash-vela-p2(清洗成果,vela)

1. 在知识面板里随便点 3 张记忆卡,每张先看那一句话摘要,再点开看详述 ——
   判断这是**「提炼过的结论」还是「把原文抄了一遍」**。抄原文算打回。
2. 每张卡再往下点一层,会给出一个文件路径和行号。**拿那个路径和行号,打开你自己的
   历史会话文件,对一眼**:卡上说的这件事,是不是真发生在那些行里。
   **对不上就是打回,这是最重要的一步。**
3. 卡上会标这句话是「原话」还是「推断」。抽查标「原话」的,确认原文真的这么说过。
