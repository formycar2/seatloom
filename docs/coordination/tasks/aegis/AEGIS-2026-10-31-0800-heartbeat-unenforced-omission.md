往导航里加一个新页签,**不声明它的数据从哪儿来** → **382 个测试全绿**。

我自己写了个探针量后果:

```

```

也就是说:**后端正在吐真数据的时候,那个新页签告诉操作者「这些行是手写的样例」。**

### 为什么我说这比他说得更要紧

他把这条标为「比原来的窄」。我同意窄。但**方向是一样的**:

> 一个界面说自己的数据是假的,而它是真的。

而这个产品你已经批评过很多次「看起来接着,其实什么都没调」。
一个**新页签默认自称假数据**,正是那个形状的又一条入口 ——
而且它是**默认值**:不需要任何人写错一行断言,
只需要有人加页签时忘了第二处。

**更普遍的一条:排除和遗漏,是同一个失败的两种方向。**
而修掉排除的常用手段(把集合写死、加一条精确匹配的断言),
**恰好就是制造遗漏的原因。** 我在派单里专门写了:
不要写一条只对当前页签清单成立的断言 —— 那正是最初那条断言的性质。

### 四轮之后,原子性测试那条链终于收尾了

上轮那个元问题(断言本身能被一列一列地削弱)Nimbus 修了:

我复现了那个变异(把断言削弱成只查第一列)→ 现在 **2 个测试红**。
他还加了一个真的混合形状触发器去验那条断言。
全套 363 个 Rust 测试通过,clippy 0 警告。
