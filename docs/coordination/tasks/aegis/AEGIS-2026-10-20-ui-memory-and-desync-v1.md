## 一、重启后回到上次的位置

### 现状(已核实行号)

`ui/src/App.tsx:213-226` **已经**按项目记住最后停在哪个标签、选中哪个对象 ——
但它存在内存里(`projectUIStatesRef`),**应用一关就丢**。

所以缺的只有一件事:**重启应用后,回到上次那个项目和那个标签。**

### 要做

1. 把"上次的项目 + 该项目的标签/选中项"落到磁盘(`localStorage` 即可,

## 二、事件类型过滤:初始收起 + 记住上次操作

### 现状(已核实行号,这里有个坑)

`ui/src/views/TimelineView.tsx:26`

```ts
const [templateFilter, setTemplateFilter] = useState<string>('all');
```

**这个 state 设了但没被使用。** 文件里有 `eventTypes`(:46)和渲染过滤按钮的地方,
但 `templateFilter` 不参与真正的过滤。**所以"记住操作"之前必须先让它真的起作用。**

### 背景数据(为什么默认收起)

账本里记忆类事件(记忆创建 243 + 召回 106)共 349 条,比派单类还多,
把用户要看的内容挤掉了。张先生 2026-10-20 裁定:**初始收起。**

### 要做

1. **先修**:让 `templateFilter` 真的过滤,别留一个改了不生效的开关
   —— 一个不起作用的开关比没有开关更糟,它让人以为已经过滤过了
2. **初始值改成收起**记忆类和话题类(`MemoryCreated`、`MemoryRecalled`、`TopicOpened`)
3. **记住上次选择**(落盘),下次打开沿用;没有记录时才用"收起"这个初始值
4. 收起的类别必须在界面上**看得见"有哪些被收起了、有多少条"**,
   并给一个能全部展开的入口 —— 收起不是隐藏

### 验收

- 重开时间线,记忆/话题类默认不占版面,但有"已收起 N 类共 M 条"+ 可展开
- 改成"全显",重开,仍是全显(记住了)
- 改成收起,重开,仍是收起
- 点某个类型能真的只剩那一类

## 三、两个遗留假数据

V5 那一单的 grep 扫描发现了两处,当时列进后续。现在处理:

### 3a `AttachSessionDialog` 的 `MOCK_PROCESSES`

已经可达(用户点得到),但它是个**进程选择器**,不是汇总数字。
**正确处理不是删掉,是标清楚它是什么**:如果这是给用户挑进程用的真实列表,
就别叫 MOCK;如果是假占位,就要么接真实进程列表,要么明说"暂无数据"。

### 3b `AppV2` 的 `MOCK_CONTACTS`

已确认是死代码:`AppV2` 从未被挂载,grep 只在它自己定义处出现。
**删掉。** 死代码里的假数据不会立刻骗人,但它会在下次有人挂载这个界面时
静默变成真的假数据。

### 验收

- 3a:界面上再也看不到冒充真实进程的假数据;要么真列表,要么明说暂无
- 3b:`AppV2` 相关假数据不再存在于源码;构建通过
