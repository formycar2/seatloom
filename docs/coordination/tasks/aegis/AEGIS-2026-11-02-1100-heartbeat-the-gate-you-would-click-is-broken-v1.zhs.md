## 🔴 变了什么:你正在跑的那个应用,它的验收门是坏的

我自己这一轮跑例行检查时,它报出来了:

```
FAIL: 验收门把仓库解析成 '/',而那不是一个 git 仓库。
      应用进程 pid 646,工作目录 /,SEATLOOM_REPO_ROOT 未设置。
      每一张卡都会显示「验收被拒 / 分支未包含验收基准」,不管分支多同步。
```

**它的后果:你点任何一张验收卡,都会收到拒绝,而你看不出为什么。**

两个原因叠在一起:

| | |
|---|---|
| 二进制是 **10-28 22:16** 的 | 四天前,那之后所有修复都不在里面 |
| 它是 **从启动台/Dock 点的**,不是用启动脚本 | 启动脚本才会设那个环境变量;从 Dock 点,cwd 是 `/`,而 `/ 不是代码仓库` |

这不是新问题 —— 10-29 就发生过同一件事,当时我修了启动脚本和检查。
**但那之后有人从 Dock 点过一次**,于是又回到坏状态。

**现在没有待验收的卡,所以它还没咬人。但等卡一开出来,你就会撞上。**
