## 变了什么

### 我上一轮的结论说过头了,这一轮改正

上一轮我向你报告:**「那个核心主张现在真的被钉住了。」**

那句话是错的。Flux 重新验之后抓到我漏掉的东西,我逐条自己复现了。

**测试是用一个延迟到 COMMIT 才触发的约束,让事务中途失败的。**
测试文件自己的注释解释了为什么必须是这样。Flux 把「延迟」改成「立即」:

```
DEFERRABLE INITIALLY DEFERRED  →  DEFERRABLE INITIALLY IMMEDIATE
```

**两个测试全绿。**

改成「立即」之后,更新语句自己就被拒绝,根本不存在写了一半的状态,
测试是因为一个**更弱的理由**过的。而「只在 COMMIT 时咬」正是这个测试
全部的意义所在 —— 它没有任何断言钉住。

我自己跑了这个变异:2 passed。恢复后工作区干净。

**我为什么漏了:** 我做的两个变异都是「删掉一段代码」,那是我能直接从
测试的断言里读出来的方向。「延迟」这条性质不在任何断言里,
**它只存在于一段注释里**。我读了那段注释,觉得它写得对,
就把它当成已经成立的事实。

**注释不是断言。**

这是同一条规律的第七次:存活的变异总是在没人想到要测的方向。
而这次我就是那个作者 —— 我定了方向,验证者按我的跑完,
又自己想了第三个。

### Flux 还抓到另外两件事,也都属实

**一、那个分支没推出去。** 本地在 `a255035`,gitlab 停在它的前一个提交,
origin 根本没有这个分支。**这个实现只存在于这一台机器的一个 clone 里。**
我上一轮验的就是这份代码,而我验的时候不知道别人拿不到它。

**二、两个测试并行跑,共用一个触发器名。** Flux 让第二个测试断言
「我开工前那个触发器没被装上」→ 红,失败的是第一个测试装的触发器。
他连跑五次干净才撞见一次,所以窗口很窄,但是真的竞争。

**三、一个更普适的问题:那个测试会静默跳过。** Flux 头两次跑它,
报的是「通过」,耗时 0.04s。真相是测试环境缺一样东西,
测试直接返回了 —— **在汇总行里,跳过和通过长得一模一样。**

一个会静默跳过的测试,比没有测试更糟:它把「我没跑」显示成「我过了」。

### 派了 Nimbus 修这四件

包括:给「延迟」这条性质加断言(要能因为有人改松它而失败)、
修掉竞争、推送分支、让 guard 不再静默跳过。
