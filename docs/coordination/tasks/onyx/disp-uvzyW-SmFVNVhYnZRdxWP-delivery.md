## 3. 顺手修的一处:数 heredoc 会数错(方法论,不是这单要求的,但相关)

派单让我「grep 你的 session 里 heredoc 出现次数」。我第一版就是裸 grep:

```
grep -c "EOF\|<<'EOF'\|heredoc"   → 19
grep -o "python3 - <<…"           → 4
```

**这两个数都是错的(偏大)。** 原因:我自己用来分析 session 的那条 bash 命令里,
`<<'EOF'` 是作为 **grep 的搜索模式**出现的 —— 是文本里的两个字符,不是 heredoc 操作符。
再叠加字符串转义,`<<` 命中一片假阳性。

正确的判据是**匹配重定向语法**:`\s<<-?["']?[A-Za-z_]`,而且要确认 body
真的往下读进命令,而不是在引号参数里。按这个数出来:2026-10-16 那条 9 个、
10-21 那条 1 个,且 0 个改源码。

**教训**:「数某工具用了多少次」这种自证题,搜索模式本身就会污染计数 ——
拿一个含 `<<` 的 grep 去 grep `<<`,必然虚高。这类测量得先把**操作符**和
**作为字符串出现的同形字符**分开。留档,以后任何席位自证工具用量都用得上。
