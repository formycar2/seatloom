## 背景

我们正在从零构建 SeatLoom v2 前端，代码在 `ui/src/app-v2/` 目录下。当前频道页面（项目频道，点击左侧联系人列表中的项目频道时右侧展示的内容）的信息排列顺序是"由整体到细节"——最宏观的目标在最上面，最紧急的阻塞在最下面。Mr. Zhang 要求改为"由细节到整体"——最紧急的信息在最上面。

`ui/src/app-v2/AppV2.tsx`

## 具体要求

### 核心任务：调整 ProjectDashboard 内部各区块的渲染顺序

当前顺序（错误的，由整体到细节）：
1. 项目目标（Goals）
2. 当前目标的阶段（Stages）
3. 当前阶段标题 + 进度条
4. DAG 工作流图
5. 正在发生（活跃工作项 + 依赖）
6. 阻塞项
7. 时间线（刚刚发生 + 更早折叠）

目标顺序（正确的，由细节到整体）：
1. **阻塞项**（最紧急，红色高亮，需要立即处理）
2. **正在发生**（活跃工作项 + 上下游依赖视图）
3. **DAG 工作流图**（当前阶段全貌）
4. **下一步**（从 DAG 区块中提取出来，独立展示）
5. **刚刚发生**（时间线，最近几条展开）
6. **当前阶段进度**（阶段标题 + 工作项完成数 + 进度条）
7. **目标和阶段**（项目目标 + 阶段列表，放最下面，默认折叠）

### 设计原则

- **最紧急的信息在最上面**：用户打开频道第一眼看到的应该是"有什么阻塞？谁在做什么？"
- **没有阻塞时不要显示空的阻塞区块**：如果没有 blocker，第一个区块就是"正在发生"
- **目标和阶段可以默认折叠**：它们是上下文信息，不是每次都需要看。加一个展开/折叠按钮
- **保持每个区块的内部设计不变**：只是调整顺序和折叠行为，不要重新设计区块内部的样式

### 额外创意空间

在完成上述核心任务后，如果你认为有改善信息展示的机会，可以尝试：

- 如果有阻塞项，在最顶部加一个紧急程度的视觉提示（比如一条红色细线或一个简短的状态摘要行）
- "下一步"区块可以更醒目一些，因为它告诉用户接下来该做什么
- 时间线的"更早"折叠部分可以更紧凑

但这些是加分项，不是必须的。核心任务是调整顺序。
