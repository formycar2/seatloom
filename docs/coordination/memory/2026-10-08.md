### 2026-10-08 — UM0 mirror fidelity dispatched (Aegis `AEGIS-2026-10-08-um0-mirror-fidelity-v1`)

- Read the Aegis dispatch in full. Symptom: Mr. Zhang sees a worker seat's input line / content render garbled in the UI.
- Grounded the diagnosis before dispatching, in code and on live tmux:
  - `ui/src/app-v2/panel/SessionTerminal.tsx` skips `fit.fit()` and early-returns out of the `ResizeObserver` whenever `paneRows`/`paneCols` are supplied — and `LiveSeatsView.tsx:553` always supplies them in the live mirror. So xterm is built at the pane's launch geometry (**219×54 measured** on the real seats today, not the 220×50 in the brief) regardless of container width, and **`cmd_pty_resize` is never called from the live mirror**.
  - `PtySession::resize` (`crates/seatloom-core/src/pty/mod.rs:500`) runs `tmux resize-pane -x/-y`. Probed on a throwaway session (tmux 3.6a): **exit 0, no effect** on single-pane windows; `tmux resize-window -x/-y` works (220×50 → 120×40 → 200×50 → 150×40 → 20×5). So `cmd_pty_resize` is currently a silent no-op that reports success — same silent-success class as the `pipe-pane -o` bug.
  - Ruled out so neither seat chases it: `capture-pane -p -e` is correct for alternate-screen TUIs (probed with `#{alternate_on}=1`; adding `-a` returns blanks), `pipe-pane` streaming is byte-clean (raw 4096-byte FIFO reads), and `@xterm/xterm` 5.5 supports truecolor natively.
